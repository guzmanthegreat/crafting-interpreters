**Answer: Since Lox uses one number type for both integers and decimals, could floating-point precision errors occur? For example, would an expression such as `0.1 + 0.2` produce exactly `0.3`? I think Lox should use double-precision floating-point numbers because they keep the language simple, although programmers should understand that some decimal values cannot be represented exactly. How should Lox compare values of different types? I think comparisons such as `1 == "1"` should return `false`, while ordering comparisons between unrelated types should produce an error. Are variables allowed to change types after assignment? Since Lox is dynamically typed, I think they should be. What values count as false in conditions? I think only `false` and `nil` should be falsey, because that rule is simple and predictable. Finally, what should happen when an undefined variable is used? I think Lox should report a runtime error rather than silently producing `nil`.**
