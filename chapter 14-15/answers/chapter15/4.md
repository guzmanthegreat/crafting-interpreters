# Chapter 15, Challenge 4: In-Place Stack Operations

`OP_NEGATE` can operate directly on the value at the top of the stack. Instead
of popping and pushing, the VM can keep `stackTop` unchanged:

```c
case OP_NEGATE:
  if (!IS_NUMBER(stackTop[-1])) {
    runtimeError("Operand must be a number.");
    return INTERPRET_RUNTIME_ERROR;
  }
  stackTop[-1] = NUMBER_VAL(-AS_NUMBER(stackTop[-1]));
  break;
```

This removes one decrement and one increment of the stack pointer. The
difference is small for one instruction, so a measurable improvement would
require a benchmark with many negations. The optimization is still useful
because the VM executes this code extremely frequently.

Similar optimizations apply to instructions whose result replaces one of their
operands. A binary arithmetic operation can pop only the right operand and
overwrite the left operand in place. Comparisons can do the same. `OP_NOT` can
also replace the top value directly. The implementation must preserve the
language's evaluation order and correctly handle type errors before changing
the stack.
